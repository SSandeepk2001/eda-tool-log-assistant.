# EDA Tool Log Assistant (RAG + ML)

A developer-focused assistant prototype for parsing Yosys/Verilator-style logs, identifying common failure signatures, and retrieving relevant troubleshooting notes through a FastAPI endpoint.

> The included logs and knowledge notes are illustrative/synthetic. This repository does not bundle proprietary EDA documentation or claim to diagnose every tool failure.

## Architecture

```text
Yosys / Verilator log
        |
        v
Log normalization + signature detection
        |
        +----> Failure category
        |
Question / error text ---> Retriever (FAISS)
                              |
                              v
                  Relevant troubleshooting notes
                              |
                              v
                         FastAPI JSON
```

## Features

- Detects common missing-module, syntax, undriven-signal, and timeout signatures.
- Creates a FAISS inner-product index over local troubleshooting notes using sentence-transformers embeddings.
- Returns retrieved context with each answer so users can inspect the basis for suggestions.
- Exposes `/health`, `/analyze`, and `/docs` endpoints.
- Includes a Dockerfile and GitHub Actions test workflow.
- Retrieval is evidence-based; no external LLM is called by default, so responses do not pretend to be generated by a hosted model.

## Setup

Python 3.11+ recommended.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Open `http://127.0.0.1:8000/docs`.

## Example request

```bash
curl -X POST http://127.0.0.1:8000/analyze \
  -H "Content-Type: application/json" \
  -d '{"log_text":"ERROR: Module `alu_core` not found!","question":"How do I debug this?"}'
```

## Docker

```bash
docker build -t eda-log-assistant .
docker run --rm -p 8000:8000 eda-log-assistant
```

The first startup may download the embedding model. For offline environments, pre-cache the model and configure your model path.

## Test

```bash
pytest -q
```

## Safety and limitations

- Treat retrieved suggestions as debugging leads, not verified root-cause conclusions.
- Confirm tool version and design context before applying a fix.
- Use only logs and documentation you are permitted to share.
- Replace the small demo knowledge base with versioned, approved internal documentation for serious use.
